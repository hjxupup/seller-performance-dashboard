Turning seller data
into daily decisions.

A seller operations dashboard that connects account hierarchies, performance trends and delivery signals in one place.

Try the interactive demo ↗Python · Dash · Pandas · Plotly · SQL
01 / CONTEXT

One operational question. Several data sources.

Account teams need to understand how a seller is doing, which delivery corridor needs attention, and whether individual accounts explain a change in performance. Bringing account information, transaction metrics and assessment results into a single interface makes those questions easier to investigate.

The original application reads three coordinated CSV snapshots, aggregates transaction-level measures with Pandas, and updates tables and Plotly charts through Dash callbacks.

03 / ENGINEERING

The original Python application

03Pandas aggregationFilter, sum, then calculate ratios
04Dash + PlotlyCallbacks, tables & 14 metric charts
Large-file loading
Selects only needed columns and reads performance data in chunks of 400,000 rows. The concatenated dataset still resides in memory.
Shared filtering
A lock-protected account filter cache lets table and chart callbacks reuse a filtered DataFrame for the same scope.
Metric correctness
Rate calculations follow aggregation, so high-volume accounts carry the appropriate weight. Missing denominators need explicit handling.
Refresh workflow
The export script includes retry paths, partition checkpoints and temporary-file replacement. The dashboard schedules a daily refresh and process restart.
04 / THIS DEMO

A self-contained portfolio reconstruction

This site recreates the original project's main interactions in HTML, CSS and JavaScript using deterministic synthetic data. It preserves the account hierarchy, monthly/YTD filters and fourteen core metric formulas. It does not connect to a company network or run the original SQL export pipeline.
